Memarlıq üslubu

Sistem event-driven mikroservis memarlığıdır. Əsas xüsusiyyətlər:

  • Multi-repo: hər servis öz git repozitoriyasıdır — monorepo və ya Gradle include() yoxdur. Hər biri öz settings.gradle, build.gradle və wrapper-i ilə müstəqildir.
  • Database-per-service: hər servisin öz PostgreSQL bazası var. Servislər bir-birinin bazasına birbaşa müraciət etmir.
  • İki əlaqə kanalı: sinxron (Gateway üzərindən REST) komandalar üçün, asinxron (Kafka) hadisələrin yayılması üçün.
  • Paylaşılan kontrakt kitabxanası: infra jar bütün enum, event və exception tiplərini mərkəzləşdirir.
Şəkil — Qatlı baxış: təqdimat → giriş → biznes → data/mesajlaşma.

Əlaqə nümunələri

Sinxron — REST (komandalar/sorğular)

İstifadəçi əməlləri (login, plan al, iddia göndər) Gateway üzərindən HTTP ilə gəlir. Gateway JWT-ni doğrulayır, sorğunu uyğun servisə marşrutlayır. Hər servis ayrıca yenidən JWT doğrulaması da edir (per-service validation).

Asinxron — Kafka (hadisələr)

Bir servisdə baş verən vacib hadisə (police yarandı, ödəniş tamamlandı) Kafka topic-inə yayımlanır. Maraqlanan servislər abunədir və müstəqil reaksiya verir. Bu, servisləri boş-bağlı (loosely coupled) saxlayır.

Şəkil — Hadisə şini: notification demək olar bütün topic-lərə abunədir; AI claim.submitted-i dinləyir, claim isə fraud.detected-i.

Servis daxili struktur (təkrarlanan şablon)

Hər biznes servisi eyni paket konvensiyasını izləyir. Bu ardıcıllıq komandanın hər servisdə eyni yeri tapmasını asanlaşdırır:

PaketMəsuliyyət
controller/REST endpoint-lər, @PreAuthorize rol yoxlaması
service/ + service/impl/Biznes məntiqi — interfeys + implementasiya
repository/Spring Data JPA interfeysləri
entity/JPA entity-ləri (UUID PK, Instant vaxt)
dto/request + dto/response/Record DTO-lar (giriş/çıxış)
kafka/XxxEventProducer / XxxEventConsumer
mapper/MapStruct Entity ↔ DTO çevirmələri
config/ · security/JWT, SecurityConfig, ConfigurationProperties
exception/GlobalExceptionHandler + XxxErrorEnum
Kod prinsipləri: Lombok hər yerdə · konstruktor injection (heç vaxt @Autowired sahə) · DTO-lar immutable record · bütün cavablar ApiResponse<T> zərfində · endpoint-lər /api/v1/ prefiksli.

Təhlükəsizlik memarlığı

  • JWT axını: Yalnız IAM token verir; bütün servislər ortaq jwt.secret ilə token-i doğrulayır.
  • Subyekt fərqi: IAM-da JWT subyekti email-dir; digər servislərdə userId (UUID) — çünki onlar istifadəçini userId ilə tanıyır.
  • Rol modeli: ADMIN / STAFF / CUSTOMER — metod səviyyəsində @PreAuthorize.
  • İki qatlı doğrulama: həm gateway, həm də hər servis JWT-ni yoxlayır (cari model: per-service validation).
  • Sızma qarşısı: başqasının resursuna müraciət 403 yox, 404 qaytarır.

Memarlıq MVP üçün sağlamdır, lakin prod-a keçməzdən əvvəl həll olunmalı bəzi məsələlər var (tam siyahı check.md-də). Önəm: 🔴 kritik · 🟠 yüksək · 🟡 orta · 🟢 aşağı.

Testləşmə memarlığı

Hər servis testlə təchiz olunub (cəmi ~190+ test, hamısı yaşıl). Yığın:

  • Unit: JUnit 5 + Mockito + AssertJ — service qatı (qərar həddləri, sahiblik/404 məntiqi).
  • İnteqrasiya: @SpringBootTest + @EmbeddedKafka + Compose PostgreSQL — hadisə zəncirləri (giriş hadisəsi yayımla, həm DB vəziyyətini, həm çıxış hadisəsini yoxla).
  • Web qatı: @WebMvcTest — rol əsaslı icazələr.
  • AI: MockWebServer ilə OpenRouter çağırışları.
  • Frontend: Vitest + React Testing Library + MSW.
Niyə inteqrasiya testləri vacibdir: Məhz onlar ödəniş ikiqat-ödəniş və police aktivləşmə (LazyInitialization) kimi reqressiyaları tutdu.
