C4 Model nədir?

C4 model proqram memarlığını 4 abstraksiya səviyyəsində təsvir edən yanaşmadır. Hər səviyyə fərqli "böyütmə" (zoom) verir: ümumi mənzərədən kod detallarına doğru. Bu sənəd E-Sağlamlıq Sığortası platformasını həmin 4 səviyyədə izah edir.

SəviyyəAdSualı cavablandırır
1System Context (Kontekst)Sistem kimlərlə və hansı xarici sistemlərlə əlaqədədir?
2Container (Konteyner)Sistem hansı icra olunan hissələrdən (servis, baza, broker) ibarətdir?
3Component (Komponent)Bir konteynerin daxili strukturu necədir?
4Code / DeploymentKomponentlər kodda və serverdə necə yerləşir?

Səviyyə 1 — System Context

Ən yüksək baxış. Platforma tək bir qutu kimi göstərilir; ətrafında istifadəçi rolları və yeganə xarici sistem (OpenRouter AI) var. Bu, B2C tək-sığortaçı modelidir — platformanın özü sığortaçıdır.

Şəkil 1 — System Context: 3 istifadəçi rolu, 1 platforma, 1 xarici AI sistemi.
Qeyd: Modeldə xəstəxana, həkim və ya digər sığorta şirkətləri yoxdur. Platforma birbaşa sığortaçı rolundadır (single-insurer MVP).

Səviyyə 2 — Container

Platformanın içini açırıq. Hər qutu ayrıca işləyən prosesi və ya data anbarını təmsil edir. Servislər bir-biri ilə iki yolla əlaqə qurur: sinxron (Gateway üzərindən REST) və asinxron (Kafka hadisələri). Hər servisin öz PostgreSQL bazası var (database-per-service).

Gateway Mikroservis PostgreSQL baza Kafka (asinxron) Xarici sistem
Şəkil 2 — Container: davamlı xətt = sinxron REST, kəsik narıncı xətt = asinxron Kafka hadisəsi.

Səviyyə 3 — Component (Claim servisi nümunəsində)

Bir konteynerin içinə baxırıq. Bütün servislər eyni qatlı (layered) struktura malikdir: Controller → Service → Repository → DB, üstəgəl Kafka producer/consumer-lər. Aşağıda Claim servisinin komponentləri göstərilib.

Şəkil 3 — Component: Claim servisinin daxili qatları və Kafka inteqrasiyası. Bu şablon bütün servislərdə təkrarlanır.

Səviyyə 4 — Deployment (Docker Compose)

Komponentlərin fiziki yerləşməsi. Bütün sistem Docker Compose ilə tək host üzərində qaldırılır. Hər servis ayrıca konteynerdir; infra kitabxanası build mərhələsində mavenLocal()-a publish olunur.

Şəkil 4 — Deployment: bütün konteynerlər bir Docker host-da. Hər servis öz prosesidir; ortaq infra jar build-də paylaşılır.
Təhlükəsizlik qeydi: Hazırkı dev quruluşunda bütün servis portları (8081–8086) host-a açıqdır, yəni gateway-i atlayaraq birbaşa müraciət mümkündür. Prod üçün yalnız 8080 və frontend açıq qalmalıdır.
